# Игрушечная модель кликового сигнала в поиске

Интерактивная страница, на которой можно покрутить параметры и увидеть, как поисковая система могла бы «помнить» клики пользователей: что происходит с позицией сайта с честными кликами и сайта, поддерживаемого накруткой. Это учебная модель, а не воспроизведение Google: все числа здесь допущения.

**Открыть и пользоваться:** `index.html` (двойной клик, ничего устанавливать не нужно) или страница GitHub Pages, если она включена.

## Область применения

Только Google. Данные по Яндексу в калибровку не берутся: системы устроены и работают по-разному. Отдельно фиксируется рынок запросов (страна и язык аудитории), потому что кликовое окно, по показаниям в суде, режется по странам и устройствам. Эксперименты из открытых источников в основном американские, поэтому перенос на русскоязычный рынок это допущение.

## Что показывает модель

- Один запрос и 30 сайтов. Показы почти полностью достаются топ-10, вне него их почти нет (зона холодного старта). Люди кликают с учётом смещения позиции (верхние результаты замечают чаще).
- Система хранит клики в «памяти». Три гипотезы о том, как она устроена, переключаются одним селектором:
  - **H1, чистое окно:** все клики окна равноценны, старше окна забываются.
  - **H2, затухание по давности:** свежие клики весят больше.
  - **H3, фильтр аномалий:** всплески обрезаются, часть накрученных кликов отбрасывается.
- Каждая линия на графике это медиана 20 запусков с разным шумом, цветная полоса показывает разброс 10–90%, поэтому выводы не зависят от одной случайной траектории.
- Пунктир на графике показывает, где был бы накрученный сайт без накрутки, поэтому разница и есть чистый эффект.
- Внизу страницы шпаргалка с мини-демо: насыщение BM25, PageRank, поправка CTR на позицию.

Пример результата (накрутка 800 кликов в неделю в течение 8 недель, старт с 1-й недели; сайт стартует за пределами топ-10): без накрутки сайт остаётся снаружи, с накруткой входит в топ-10 и остаётся там во всех трёх гипотезах (при качестве 0,8 около 6-го места на 103-й неделе против около 11 без накрутки). Это во многом следствие допущения о почти нулевых показах вне топ-10, а не факт о Google.

## Что подтверждено, а что нет

| Статус | Что |
|---|---|
| подтверждено судом | Система Navboost использует клики, окно данных 13 месяцев (показания и решения по делу United States v. Google) |
| вероятно | Поправка на смещение позиции (стандарт научной практики) |
| гипотеза | Как именно система забывает или отсекает клики, H1/H2/H3 |
| гипотеза | Внешний слой данных (Chrome, YouTube, Android) как независимая оценка качества сайта. Подтверждений для YouTube в веб-поиске не найдено |
| допущение | Все числовые константы модели |

Из утечки документации Google (2024) известны только названия полей, а не веса и не факт использования каждого поля в ранжировании.

Источники для старта: [United States v. Google LLC](https://en.wikipedia.org/wiki/United_States_v._Google_LLC_(2023)), [утечка документации 2024](https://en.wikipedia.org/wiki/2024_Google_Search_documentation_leak). Перед цитированием стоит открыть первоисточники: судебные решения и показания.

## Ограничения

Один запрос, 30 сайтов, три числа на сайт (база, привлекательность, качество). Нет байесовского сглаживания малых выборок, срезов по странам и устройствам, влияния других сигналов. Модель показывает логику рассуждений, а не истину.

## Как калибровать на реальных данных

1. Прочитайте `HYPOTHESES.md`: что предсказывает каждая гипотеза.
2. Заполните `data/observations_template.csv` обезличенными наблюдениями (идентификатор проекта вместо названия, недели вместо дат). **Данные клиентов под NDA в репозиторий не кладём.**
3. Сравните форму кривой после остановки накрутки или просадки с кривыми модели.

## Как включить страницу на GitHub Pages

Settings → Pages → Source: «Deploy from a branch» → ветка `main`, папка `/ (root)` → Save. Через минуту страница откроется по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.
